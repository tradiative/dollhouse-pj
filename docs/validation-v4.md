# v4 검증 기록 — 실제 계정 요청은 아직 0건

2026-10-24 (한국 시간), 앱 0.4.0. OAuth/모델 응답은 모의 공급자로만 검사했습니다. 이번 변경으로 앱 자격·서버 배포·실제 로그인·실제 이미지 처리·범용 재현 품질을 통과 처리하지 않습니다.

## 실제 검사 결과

- Node 24.19.0: TypeScript + production Vite build 통과. 기존의 500 kB 초과 청크 안내는 남아 있습니다.
- 단위·HTTP 검사 **45개 통과**. 기존 38개에 VM 조건, 새 app OAuth 이전/서명/호스트 보존/PC 갱신 동결/중복 수신/실행부 잠금, 소유자 접근 경계, 응답 완료와 형상 실패 구분, 실제 loopback 리스너와 브라우저 비밀 값 분리, 정지 스트림/브라우저 취소 전파 7개를 추가했습니다.
- 보호된 서버 검사는 Host를 보존하는 Node HTTP 요청으로 TLS 프록시의 내부 전달을 모델링했습니다. 실제 인터넷 HTTPS 서버 검사와 구분합니다. native fetch가 Host 재정의를 무시하는 점을 확인하고 검사 전달 방식을 수정했습니다.
- `npm run build:runtime` 통과. compiled Node 실행부의 `/api/health`는 0.4.0·production·aiConfigured:false로 응답했으며, 이 실행부가 제공한 production 화면에서 기존 Chromium **17개 검사 통과**(1.6분). 모의 AI 1건의 UI→동일 형상·파일, 원본 보존, 편집 잠금, PDF, 취소, 내보내기·복원과 휴대폰 화면을 검사했습니다. 실제 AI 요청은 아닙니다.
- 마지막 접근 제한·완료 ID 검사 보완 후 관련 OAuth/VM 검사 **12개 재실행 통과**. 나머지는 변경되지 않아 이유 없는 전체 반복은 하지 않았습니다.
- `git apply --check docs/license-proposal.patch` 통과. **라이선스 변경안 적용은 하지 않았습니다.**
- Docker Compose 2.40.3의 설정 검사와 SSH 강제 명령의 셸 구문 검사 통과(가상 example.org 값). 실제 호스트 설정이 아닙니다.
- Docker 28.4.0에서 Node 공식 이미지의 digest 기반 다운로드까지 완료했으나 두 `npm ci` 단계에서 장시간 진행이 없어 빌드를 중단했습니다(exit 130). 전체 컨테이너 이미지 빌드·실행은 **미완료**입니다. TLS/검증을 끄거나 성공 처리하지 않았습니다. 호스트의 잠금 의존성으로 빌드한 Node 실행부 검증과 구분합니다.
- 실제 SSH 서버·전용 키·Windows/macOS 실행기·각 OS 자격 증명 ACL은 미실시입니다. 준비한 코드를 사용자용 설치 완료 앱으로 보고하지 않습니다.

- 내부 Chromium 수동 검사: 연결 준비 화면·MIT 변경안 다운로드·개발자 ZIP 다운로드를 직접 열었습니다. ZIP 226개 파일/4,688,417바이트의 SHA-256을 모두 재검사했고 원본 이미지·인증 기록이 없음을 확인했습니다. 휴대폰 가로 넘침 없음, 기존 공개 사례 ZIP의 64개 STL·mm 안내 보존. 증거: [local-validation-v4.json](local-validation-v4.json). 공개 사이트에서도 같은 검사를 통과했습니다.
