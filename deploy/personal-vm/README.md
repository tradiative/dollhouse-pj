# Developer deployment package — not a completed hosted service

No license change, host, billable service, SSH key or real OAuth authorization has been provisioned by this package. Do not ask the owner to run these commands. Follow docs/connection-v4.md and docs/validation-v4.md before activation.

1. Obtain the owner's decision on docs/license-proposal.patch and review applicable OSS/provider conditions. Review the full hosting quote, quotas, expiry and spending controls with the owner before creating a service. An existing GitHub Pages site is not an inference runtime.
2. Provision an owner-controlled Linux host with Docker/Compose and a real DNS/TLS hostname. Keep the application repository, reviewed.env and forced command root/operator-owned and not writable through the connector key. Build with the included Dockerfile. The template intentionally contains no working domain or secret. Never put an OAuth token in an environment variable or public Pages configuration.
3. The developer supplies deploy/personal-vm/reviewed.env with TRADIATIVE_PUBLIC_ORIGIN, TRADIATIVE_HOST and TRADIATIVE_OSS_REVIEWED=true **only after the relevant review**. This flag records an operator decision, not automatic provider approval. Use `docker compose --env-file deploy/personal-vm/reviewed.env -f deploy/personal-vm/compose.yaml config` to check the final, non-secret setup. Only ports 80/443 may be public. Do not publish runtime port 3000.
4. Create a NEW per-installation SSH key named tradiative_vm_ed25519. Verify the server host key using the provider's trusted console and install its known_hosts entry. Restrict this key to the included ssh-import.sh forced command, with no forwarding, PTY or other shell access. The dedicated server account must not accept password/sftp/other keys and cannot modify the application or forced command. Docker access is powerful; the operator must validate the actual isolation rather than grant a generic interactive Docker account. No pre-existing agent/platform/Codex key is reused.
5. Prepare the owner's connector distribution with Node 24, supported system SSH, the bundled connector (runtime/server/connector.mjs), necessary production dependencies and private target configuration. The developer supplies absolute paths in target.json: version=1, ossReviewed=true, origin, sshHost, sshUser, identityFile, knownHostsFile, remoteImporter=/opt/tradiative/server/vmImport.mjs, remoteStateDirectory=/var/lib/tradiative. Target configuration and private key stay OFF the public site/Git/download package. Check Windows ACL or Unix owner-only permissions. Launching `node runtime/server/connector.mjs <target.json>` opens the actual PC browser itself. Package the launcher for the owner's real OS before giving a user download. Windows/macOS execution and actual SSH remain untested here.
6. Before OAuth, test the configured SSH host/key and exact forced command without sending any existing credentials. The import command stops the runtime, runs the importer against its protected volume and restarts. Initial runtime login is closed until the owner record arrives. Stale runtime.lock after an abnormal kill must be recovered by the operator after confirming no process owns it; do not automatically delete a possibly active lock. In-flight old jobs may prevent a quick handoff; a timeout leaves the PC frozen and requires developer confirmation/retry.
7. The owner chooses a workroom password in the PC connector, completes official sign-in and plan-use consent. Only this new app-owned session is sent over pinned SSH stdin. The VM verifies the ID token again, preserves its distinct host ID and acknowledges import. The PC erases its copy after that acknowledgement and never races the VM's refresh. A repeated transfer receipt must not overwrite later rotated credentials. Provider-side per-host attribution/revocation for transferred sessions is not available.
8. Verify public HTTPS, session login/logout, access denial without the owner's session and no credential exposure. Add a top-level link from the existing Pages entry only AFTER the real URL is verified. Preserve Pages projects; initially move selected projects using existing original-inclusive ZIP backup/import. Cross-origin localStorage/IndexedDB is not shared.
9. With the owner present, fetch that account's model catalog, choose an image-capable model and run ONE small authorized image. No SDK/browser retries. Server defaults/caps: 1 request, at most 3 validation attempts/90 seconds total, 6 images, one active job. Record response.completed separately from geometry validity. Then open the actual model, download and parse its SVG/DXF/STL/CSV files. Populate C01–C10 with actual evidence and leave T13–T15 pending until independently tested.

Operations: keep the original SSH configuration safe, update TLS/OS/application, back up protected volumes securely, and use the PC connector again for explicit renewal after revocation or session expiry. Owner workroom sessions expire after 8 hours and on runtime restart. No public sign-up or provider credential import endpoint exists. No server service or recurring charge was created in this work.
